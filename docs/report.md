\## Ответы на контрольные вопросы



1\. \*\*Что такое OpenTelemetry? Атрибуты, события, контекст, журналы, трассировки, показатели?\*\*

OpenTelemetry (OTel) — это открытый фреймворк для сбора телеметрии (метрик, логов и трассировок).

\*Атрибуты\* — это пары ключ-значение с метаданными (например, `http.method="GET"`). \*События\* — структурированные сообщения внутри спана. \*Контекст\* — механизм передачи информации о трейсе между сервисами. \*Журналы, трассировки и показатели (метрики)\* — это три основных сигнала наблюдаемости (MLT).



2\. \*\*Что такое наблюдаемость? Надежность и показатели?\*\*

Наблюдаемость (Observability) — это способность понять внутреннее состояние системы по ее внешним выходным данным (телеметрии). Надежность (Reliability) — способность системы выполнять свои функции без сбоев в течение заданного времени. Показатели (SLI/SLO) — измеримые метрики, по которым оценивается надежность.



3\. \*\*Что такое трассировка? Что такое распределенная трассировка? Как собирать и какие проблемы?\*\*

Трассировка — это запись пути выполнения запроса. Распределенная трассировка отслеживает запрос, проходящий через несколько микросервисов. Собирается через прокидывание контекста (например, заголовок `traceparent`). Проблемы: рассинхронизация часов на разных серверах, сложность интеграции, потеря контекста при сетевых сбоях.



4\. \*\*Сигналы OpenTelemetry: трассировки, метрики, логи?\*\*

Трассировки показывают путь запроса и время его обработки на каждом узле. Метрики — числовые агрегированные данные о работе системы (CPU, RPS). Логи — текстовые записи о произошедших событиях.



5\. \*\*Инструменты OpenTelemetry: автоматические, ручные, библиотеки?\*\*

Автоматические (zero-code) — подключаются через агенты и перехватывают вызовы без изменения кода (как `opentelemetry-instrument`). Ручные — использование API/SDK для создания кастомных спанов и метрик. Библиотеки — готовые пакеты для интеграции с фреймворками (Flask, Requests и т.д.).



6\. \*\*Компоненты OpenTelemetry: спецификация, сборщики, библиотеки, экспортеры, авто-инструменты?\*\*

\*Спецификация\* — стандарты API и SDK. \*Сборщик (Collector)\* — прокси для приема, обработки и экспорта данных. \*Библиотеки\* — SDK для языков. \*Экспортеры\* — модули для отправки данных в бэкенды (Jaeger, Prometheus). \*Авто-инструменты\* — агенты для автоматического сбора.



7\. \*\*Ресурс OpenTelemetry (телеметрия)?\*\*

Ресурс — это набор неизменяемых атрибутов, описывающих сущность, которая генерирует телеметрию (например, имя сервиса `service.name`, версия, имя хоста).



8\. \*\*Экспортеры OpenTelemetry?\*\*

Это компоненты, которые принимают данные от SDK и отправляют их во внешние системы мониторинга. Примеры: OTLP (стандартный протокол), Jaeger Exporter, Prometheus Exporter, Console Exporter.



9\. \*\*Что такое Prometheus? Как работает Prometheus?\*\*

Prometheus — это система мониторинга и база данных временных рядов. Работает по pull-модели: периодически сам отправляет HTTP-запросы (scrape) на эндпоинты приложений (например, `/metrics`) и сохраняет полученные метрики.



10\. \*\*Концепции Prometheus?\*\*

Модель данных (метрика + набор лейблов), временные ряды, сбор метрик (scraping), язык запросов PromQL, алертинг (Alertmanager) и обнаружение сервисов (Service Discovery).



11\. \*\*Типы метрик?\*\*

В Prometheus четыре основных типа: \*Counter\* (счетчик, только растет), \*Gauge\* (датчик, может расти и падать), \*Histogram\* (гистограмма, распределение значений по бакетам), \*Summary\* (квантили).



12\. \*\*Запрос и преобразование данных Grafana?\*\*

Запросы выполняются на языке источника данных (например, PromQL для Prometheus или LogQL для Loki). Преобразования (Transformations) позволяют объединять данные из разных запросов, переименовывать поля, фильтровать и сортировать их перед отображением.



13\. \*\*Источники данных Grafana?\*\*

Grafana поддерживает десятки источников: Prometheus, Loki, Elasticsearch, PostgreSQL, MySQL, InfluxDB, Jaeger и многие другие.



14\. \*\*Панели мониторинга Grafana?\*\*

Dashboard — это набор панелей (графики, таблицы, синглстаты), объединенных по какой-то теме. Панели могут быть интерактивными (с переменными/фильтрами).



15\. \*\*Процесс обработки журналов Grafana Loki?\*\*

Loki принимает логи от агентов (например, Promtail), индексирует \*\*только метаданные (лейблы)\*\* (например, `job="flask-app"`), а сами тексты логов сжимает и хранит в чанках. Это делает его очень дешевым по сравнению с Elasticsearch.



16\. \*\*Варианты сборки журналов для Grafana Loki?\*\*

Сборщиком по умолчанию является агент \*\*Promtail\*\*. Также используются: Grafana Alloy (новый стандарт), Docker Driver (плагин для отправки логов прямо из контейнеров), Fluentd, Fluent Bit.
